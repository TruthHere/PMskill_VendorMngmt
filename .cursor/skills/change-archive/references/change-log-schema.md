# Change Log Schema

## 文件

| 项 | 约定 |
|----|------|
| 路径 | `{project_root}/{项目名}_change_log.csv` |
| 项目名 | 与 `.skill/project.json` 的 `project_name` 一致 |
| 编码 | UTF-8（可带 BOM） |
| 首行元数据 | `# 最后更新,<ISO8601>`，下一行表头 |
| 模板 | `../assets/change_log.template.csv` |

**不修改**采购包 Tracker、**不写入**履约卡片。金额与状态写本 CSV。

**手改优先**：PM 可直接改本 CSV。Skill 3 只跟邮件写入，不对手改做二次判断或纠偏；发现「已取消」则只归档、不推进。

现金流 / 请款页「已确认变更」**直接读本表**的「最终确认金额」（跳过已取消行）。

## 主键

`变更序号` + `采购包名称`。一条变更通常只挂一个包。

## 列定义

| 列名 | 说明 |
|------|------|
| 变更序号 | COD/COT 等 |
| 采购包名称 | 与 Tracker / 包文件夹一致 |
| 供应商 | 可从 Tracker 带出 |
| 变更内容 | 短标题；勿塞正文长段 |
| 预估金额 | COD 阶段；**不含税** |
| 最终确认金额 | 商务金额确认；**不含税**；→ `confirmed_amount` |
| 时间影响 | 如 No schedule impact |
| 当前状态 | 总览标签（下表显示名） |
| COD已发出 … Change PO下发 | **里程碑戳**：有值=已达成；首次锁定；优先邮件 Date |
| 已取消 | 终态侧枝戳；手改取消时填时间或任意非空即可 |
| 归档路径 | 相对项目根，优先 `…/04_变更洽商/` |
| 备注 | pending 原因、攒 PO、手改说明等 |

里程碑列序：`COD已发出` → `PMI已发出` → `技术文件提交` → `技术审核中` → `技术确认` → `商务确认` → `商务金额确认` → `Change PO下发` → `已取消`。

客户确认 COD **不**另开列。顾问确认 ≡ 技术确认。

## 当前状态显示名

| 顺序 | 显示名 |
|------|--------|
| 1 | COD 已发出 |
| 2 | PMI 已发出 |
| 3 | 技术审核中 |
| 4 | 技术确认 |
| 5 | 商务确认 |
| 6 | 商务金额确认 |
| 7 | Change PO 下发 |
| — | 已取消（侧枝终态，不占 1→7 序位） |

### 推进规则

1. 主路径只前进不回退；禁止跳级（除非用户显式补录）。
2. 先技术后商务；乱序 → pending。
3. 重复邮件：不覆盖已有里程碑戳。
4. 无 COD 行却来 PMI → pending。
5. 停在商务金额确认暂不发 Change PO：**合法**。
6. **已取消**：手改 `当前状态=已取消` 或填「已取消」列后，Skill 3 不再自动推进；前序戳保留。

## 金额

- 预估 / 最终均为不含税；格式同 Skill 1（如 `¥20,000.00`）。
- 含逗号须 CSV 加引号；最终值**不**覆盖预估列。
- 税口径不清 → pending；禁止自算核定。

## Change PO 关联

1. 变更序号  
2. 该包唯一「已商务金额确认且未 Change PO」行  
3. 多条 → pending  

不单列 PO 号。

## 下游怎么读本表

| 读者 | 认什么 |
|------|--------|
| 现金流 Skill 4 | 同包、有「最终确认金额」、非已取消 → 计入「已确认变更」（默认挂尾款） |
| 请款页 payment-form | 同上合计 → Excel「Variations to-date」 |
| 履约卡片 | **不读、不展示** |
