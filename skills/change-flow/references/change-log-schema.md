# Change Log Schema

## 文件

| 项 | 约定 |
|----|------|
| 路径（机读） | `{project_root}/.skill/change_log.csv` |
| 路径（给人看） | `{project_root}/{项目名}_Change Log.xlsx` |
| 项目名 | 与 `.skill/project.json` 的 `project_name` 一致 |
| 编码 | UTF-8（可带 BOM） |
| 首行元数据 | `# 最后更新,<ISO8601>`，下一行表头 |
| 模板 | `../assets/change_log.template.csv` |

**不修改**采购包 Tracker、**不写入**履约卡片。金额与状态写本 CSV。

**手改优先**：PM 可直接改本 CSV。Skill 3 只跟邮件写入，不对手改做二次判断或纠偏；发现「已取消」则只归档、不推进。

现金流 / 请款页「已确认变更」**直接读本表**的「最终确认金额」（跳过已取消行）。

## 与典型 COD Tracker 对照

现场常见的 `COD Tracker.xlsx` → Change Log 页，我们收录：**Code / To / Change Content / Description / Amount / Status**。  
**不收录**：Deciplines（专业）、Note、Who to blame。

| 典型列 | 我们的列 | 说明 |
|--------|----------|------|
| Code | 变更序号 | COD076 / COD-IT-008 等 |
| To | 供应商 | 另有「采购包名称」对齐 Tracker |
| Change Content | 变更内容 | **短标题**（扫目录用） |
| Description | 详细说明 | **长说明**（COD 正文浓缩）；可多行 |
| Amount | 预估金额 + 最终确认金额 | 拆成两列更清楚：COD 写预估，商务确认写最终；均为**不含税** |
| Status | 当前状态 | 我们更细（COD→…→Change PO），不是对方那种几乎全是 `F Form/PO change` |
| （无） | 时间影响、里程碑戳、已取消、归档路径 | 我们多出来的流程字段 |
| Deciplines | — | **不收录** |
| Note | — | **不收录**（过程日记改由里程碑戳 + 邮件归档承担） |
| Who to blame | — | **不收录** |

## 主键

`变更序号` + `采购包名称`。一条变更通常只挂一个包。

## 列定义

| 列名 | 说明 |
|------|------|
| 变更序号 | COD/COT 等 |
| 采购包名称 | 与 Tracker / 包文件夹一致 |
| 供应商 | 可从 Tracker 带出（≈ 典型 To） |
| 变更内容 | 短标题；勿塞正文长段 |
| 详细说明 | COD 正文里的 Description；可多行；首次写入后不覆盖手改 |
| 预估金额 | COD 阶段；**不含税** |
| 最终确认金额 | 商务金额确认；**不含税** |
| 时间影响 | 如 No schedule impact |
| 当前状态 | 总览标签（下表显示名） |
| COD已发出 … Change PO下发 | **里程碑戳**：有值=已达成；首次锁定；优先邮件 Date |
| 已取消 | 终态侧枝戳；手改取消时填时间或任意非空即可 |
| 归档路径 | 相对项目根，优先 `…/04_变更洽商/` |
| 备注 | pending 原因、攒 PO、手改说明等（**不是**典型 Note 日记） |

里程碑列序：`COD已发出` → `PMI已发出` → `技术文件提交` → `技术审核中` → `技术确认` → `商务确认` → `商务金额确认` → `Change PO下发` → `已取消`。

客户确认 COD **不**另开列。顾问确认 ≡ 技术确认。

## 当前状态显示名

| 顺序 | 显示名 |
|------|--------|
| 1 | COD 已发出 |
| 2 | PMI 已发出 |
| 3 | 技术审核中 |
| 4 | 技术确认 |
| 5 | 商务确认 |
| 6 | 商务金额确认 |
| 7 | Change PO 下发 |
| — | 已取消（侧枝终态，不占 1→7 序位） |

### 推进规则

1. 主路径只前进不回退；禁止跳级（除非用户显式补录）。
2. 先技术后商务；乱序 → pending。
3. 重复邮件：不覆盖已有里程碑戳；不覆盖已有「详细说明」（除非原为空）。
4. 无 COD 行却来 PMI → pending。
5. 停在商务金额确认暂不发 Change PO：**合法**。
6. **已取消**：手改 `当前状态=已取消` 或填「已取消」列后，Skill 3 不再自动推进；前序戳保留。

## 金额

- 预估 / 最终均为不含税；格式同 Skill 1（如 `¥20,000.00`）。
- 含逗号须 CSV 加引号；最终值**不**覆盖预估列。
- 税口径不清 → pending；禁止自算核定。

## Change PO 关联

1. 变更序号  
2. 该包唯一「已商务金额确认且未 Change PO」行  
3. 多条 → pending  

不单列 PO 号。

## 下游怎么读本表

| 读者 | 认什么 |
|------|--------|
| 现金流预测 | 同包、有「最终确认金额」、非已取消 → 计入「已确认变更」（默认挂尾款） |
| 请款页 payment-sheet | 同上合计 → Excel「Variations to-date」 |
| 履约卡片 | **不读、不展示** |
