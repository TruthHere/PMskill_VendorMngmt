每个技能的输入数据、输出产物、潜在限制 & 需要确认的问题 — 逐项过一遍

一、五大流程环节 Skill
1 合同履约条件结构化 Skill 邮件驱动 · 归档与结构化建档
输入 INPUT
0.项目初始化邮件（阶段 0：正文 + 进度计划附件）
阶段 0 时 Tracker 无采购包行；Skill 自动建企微表。必须先完成初始化
1.项目经理转发的邮件（支持转发 + 发件 BCC）
RFP、顾问确认技术文件、Raise PO、合同、付款指示邮件等；微信文件整理后邮件转发
2.邮件附件（PDF/Word/图片/DWG/Excel 等）
收到当下同步 OCR/解析，非事后批量提取
3.按采购包类型的字段模板
纯供应 / 供装 / 顾问 / 总包 四类，付款节点数以类型区分
输出 OUTPUT
1.Tracker（企微在线表格 · 每项目一张）
每直采包一行总览；Skill 自动建表、API 自动写入；详情见卡片 HTML
2.履约条件卡片 HTML（每包一份，可导出 PDF）
付款节点、验收标准、约束条款；付款以合同为准
3.标准化供应商文件夹（01~09 子目录 + 标准命名文件）
RFP 正文→07_往来文件；图纸→02_图纸；报价/合同→01_合同报价
4.节点提醒（企微对话机器人）
到货日前 N 天、质保金到期等；为 R1 提供扫描数据
处理链路：邮件送达（转发/BCC）→ 同步归档 + 标准命名 → OCR/文档解析 + 字段提取 → 企微 API 更新 Tracker 行 + 增量更新卡片 HTML → 不确定字段经企微对话机器人确认 → 持续扫描生成提醒
潜在限制 & 风险
风险 扫描件 OCR 准确率影响付款比例等关键字段
风险 邮件主题/正文识别采购包可能误关联（待调试）
存储 文件夹建在本地电脑，根路径于阶段 0 指定
依赖 阶段 0 必须先完成；一包一供应商、一般一封 RFP
边界 总包滚动进度款、付款结构核验 → Skill 2；变更/请款分析由 Skill 2/3 负责
已确认（2026-07）
✓ Tracker = 企微在线表格（自动建表/API 写入）；邮件 = 转发 + BCC；反馈 = 企微对话机器人
✓ 文件夹 = 本地电脑，根路径在阶段 0 与项目信息一并指定
✓ 总包滚动进度款、付款结构核验 → Skill 2；付款变更可随改并留历史，无审批流
2 请款合理性自动核验 Skill 中间过程请款阶段
输入 INPUT
1.供应商请款单（金额、申请节点、请款事由）
格式：Excel/表单/微信消息截图？需明确统一格式
2.该供应商的履约条件卡片（Skill 1产出）
含：合同约定付款比例、里程碑触发条件、前置条件
3.当前实际进度证据
现场带水印照片（带时间+地点）、监理书面确认、进度百分比
4.已支付历史请款记录
该包累计已付金额、上期是否已抵扣、发票状态
输出 OUTPUT
1.《请款审核意见》含审核结论
通过 / 建议核减XX元 / 退回补充资料，每条结论附依据
2.建议核减金额明细
超出合同比例部分、前置条件不满足部分、与进度不符部分
3.需补充资料清单
缺发票、缺进度照片、缺监理签字等，逐条列出
处理链路：请款单结构化解析 → 关联合同履约卡片（取付款条件） → 关联历史支付记录 → 解析进度证据（照片识别+表单提取） → 多维度比对（金额/比例/前置条件/资料齐备） → 生成审核意见
潜在限制 & 风险
风险 现场照片真实性问题：照片可能不是当天的、同角度摆拍、或并非本项目的工地
风险 进度百分比的主观性：监理/供应商/现场三方对"完成度"的认定可能不一致
依赖 Skill 1的履约卡片必须准确，否则核验基准就是错的
依赖 付款节点"soft condition"难以量化：如"甲方代表口头认可"这类前置条件AI无法自动验证
需要你确认
Q1 请款单目前是什么格式？Excel模板统一吗？还是微信/邮件里发个金额就来了？
Q2 进度证据你们现在怎么收？监理签字是纸质还是电子？现场照片有平台管理吗？
Q3 核减建议AI直接生成后，是给你审核再发，还是AI直接退回供应商？你们希望AI的"决策权限"到什么程度？
3 变更影响连锁分析 Skill 过程变更阶段
输入 INPUT
1.变更指令/洽商记录（变更内容、涉及区域、变更原因）
格式：变更单/签证单/洽商记录，可能含图纸附件
2.「采购包关联图谱」— 预设的包间依赖关系
核心输入！需人工先定义：如天花造型变更→关联灯具/空调风口/消防点位/石膏板
3.各关联包的当前执行状态
已下单/已到货/已安装/已完成 — 判断变更是否影响已完成的包
输出 OUTPUT
1.《变更影响地图》
可视化展示：源头变更 → 波及的直采包（按影响程度分级：必须改/可能改/无影响）
2.《波及供应商通知清单》+ 通知草稿
列出每个受影响的供应商该暂停/改规格/改数量/改交期
3.《需重新核量/询价清单》+ 待办派发
自动创建任务：设计师确认量、成本人员询价
4.变更前后量价记录（链接到该包结算底稿）
处理链路：变更指令解析（提取关键词+涉及区域+变更类型） → 在关联图谱中匹配波及路径 → 查询各波及包的当前状态 → 生成影响分级 → 生成通知清单 & 待办任务 → 记录变更历史链接结算
潜在限制 & 风险
风险 关联图谱的完整性是核心瓶颈：如果漏定义了一个关联（如没录入"踢脚线与地面石材关联"），AI就不会提醒
风险 变更指令表述模糊："天花造型微调" — AI可能不理解"微调"的实际影响范围
依赖 关联图谱的维护成本：每个新项目可能有新的包组合，图谱需要持续更新
依赖 波及包的实时状态数据：如果状态更新不及时，可能对已完成包误发变更通知
需要你确认
Q1 关联图谱你们现在有吗？还是靠脑子记？如果要建，你预估每个项目大概有多少个直采包、多少对关联？
Q2 变更指令来源是统一的变更单系统，还是微信/会议上口头说的？如果能统一模板（变更类型下拉+涉及材料/区域/部位），AI就准确得多
Q3 波及包的"当前状态"数据现在能拿到吗？是实时还是靠人报？
4 多源数据交叉核验 Skill 验收交付阶段
输入 INPUT
1.供应商《到货/安装完成确认单》（数量、规格、自评合格率）
格式：供应商自身的验收单、送货单、安装确认单
2.监理进度确认（数量、合格率、验收意见）
监理报告/监理日志/监理APP确认截图
3.现场带水印照片（含时间+GPS+拍摄角度）
AI需能识别：材料数量、破损/瑕疵、安装完成面
4.特殊验收条件清单（如破坏性试验报告、防火检测报告）
某些材料需要额外检测报告才能视为验收通过
输出 OUTPUT
1.《验收一致性报告》
三个数据来源的比对结果，无争议项×N，争议项×N
2.争议项高亮 + 自动提问
"XX木饰面：供应商报1000平，监理确认980平，差额20平如何处理？"
3.特殊验收条件达标检查
漏掉「破坏性试验报告」等特殊条件时自动标红
4.通过验收的包直接触发请款流程
无争议项自动流转到Skill 2的请款环节
处理链路：三方数据录入/上传 → 图片AI识别（计数+质量检测） → 表单数据解析 → 维度对齐（按包/按材料/按区域） → 三方数据比对 → 差异分级（自动通过/需人工仲裁/严重差异） → 生成报告 → 触发下游动作
潜在限制 & 风险
风险 照片计数的准确率：AI从照片中数木饰面板、数灯具数量，遮挡/重叠/角度可能导致误差
风险 破损检测的准确率：细小裂缝、轻微色差AI可能无法识别，而这些都是验收争议的常见点
依赖 三方数据的维度对齐：供应商按「件」、监理按「平」、照片里只能看「块」—— 单位不一致时如何换算？
依赖 差异容忍阈值需定义：差2%自动通过、差5%人工确认、差10%标红——这个阈值需要你定
需要你确认
Q1 现场照片目前谁拍？用什么工具？有没有水印（时间+GPS）？如果没有，水印需要先落实
Q2 监理的确认格式统一吗？是APP里填表单，还是纸质签字后拍照？
Q3 差异容忍阈值你心里的标准是什么？2%/5%/10%还是其他？不同类型材料是不是不一样？
5 全链路回溯结算 Skill 结算阶段
输入 INPUT
1.合同PO号（唯一标识）
这是唯一输入！触发后AI自动拉取全链路数据
2.（自动拉取）原始合同价 — 来自Skill 1履约卡片
3.（自动拉取）所有已确认变更 ± 金额 — 来自Skill 3记录
4.（自动拉取）过程扣款/罚款单 — 来自项目管理记录
5.（自动拉取）已支付请款总和 — 来自Skill 2记录
6.（自动拉取）质保金应留比例 — 来自Skill 1履约卡片
输出 OUTPUT
1.《结算一页纸》核心公式
应结算 = 合同价 + 变更(±) - 罚款 - 已付 - 质保金
2.每项金额的凭证链接/跳转
点击每笔变更可追溯到原始变更单，每笔罚款可看罚款单
3.可直接与供应商对账的结算单草稿
格式：Excel/PDF，包含明细行+汇总行
处理链路：输入PO号 → 系统自动检索关联的：合同数据(Skill1) + 变更记录(Skill3) + 罚款记录 + 支付记录(Skill2) → 按公式汇总 → 逐项附凭证链接 → 生成结算单 → 标记「待对账确认」
潜在限制 & 风险
风险 全链路数据完整性依赖：如果前面任何一个Skill的数据缺失（如有一笔变更没录入系统），结算就不准
风险 历史遗留项目的旧数据：之前没用这套系统的项目，历史变更/罚款/请款记录可能散落在邮件和微信里
依赖 最依赖前面4个Skill的数据质量和覆盖率，是"最终验收"性质的Skill
依赖 分包/变更价差：同一变更可能有"暂估价"和"最终核定价"，用哪个价需要规则
需要你确认
Q1 扣款/罚款记录现在怎么管的？有统一台账吗？还是散落在Excel/邮件/微信里？
Q2 结算单的最终格式你们有模板吗？甲方/财务对格式有要求吗？
Q3 新上一个项目怎么处理历史数据？是先做数据迁移/补录，还是新老划断、只从某个节点之后启用？
二、高阶统筹 Skill（跨周期全局控制）
R1 全局风险预警 Skill 跨包扫描 · 定时巡检
输入 INPUT
1.预警规则集（可配置）
例：直采包超期7天未请款 / 变更超3天未发起关联评估 / 质保金预留比例异常 / 供应商连续2次请款被退回
2.所有供应商的实时状态数据流
来自Skill 1-5的结构化数据：履约节点进度、请款状态、变更记录、验收结果、付款记录
3.规则触发历史（避免重复报警）
输出 OUTPUT
1.「管理例外」清单
只展示触发预警的异常项，正常的不显示 — 让你只看例外
2.推送消息（企业微信/钉钉/邮件）
按严重程度分级：红色紧急 / 黄色提醒 / 蓝色信息
3.趋势预警
虽然还没超期，但按当前进度推算将在3天内超期 → 提前预警
潜在限制 & 风险
风险 误报太多导致"狼来了"效应：阈值设太严，天天报警，人就麻木了
风险 漏报：阈值太松，真正有风险的情况没报出来
依赖 严重依赖Skill 1-5的数据完整性和实时性
需要你确认
Q1 预警规则你想设哪些？我列了几个例子（超期7天/变更3天/质保金异常），哪些你觉得最需要？阈值你觉得多少合适？
Q2 推送渠道：企业微信？钉钉？邮件？还是系统内有消息中心？
Q3 预警频率：每天几点扫一次？还是实时触发？
R2 供应商画像 Skill 数据积累 · 辅助招标决策
输入 INPUT
1.该供应商在所有项目中的历史数据
来源：Skill 1-5积累的合同履约、请款、变更、验收、结算数据
2.评价维度 & 权重配置
例：累计变更率(25%) / 平均延误天数(25%) / 一次验收合格率(30%) / 配合度(20%)
输出 OUTPUT
1.供应商合作档案（一页纸）
累计合作项目数、总金额、平均延误天数、变更率、一次验收合格率
2.招标风险提示
"该木作供应商近三次项目平均延误12天，变更率达18%，建议审慎"
3.供应商排名/对比
同类供应商（如石材供应商A/B/C）横向对比，辅助招标短名单
潜在限制 & 风险
风险 新供应商冷启动：没有历史数据，画像为空，无法评价 — 是否影响其短名单入围？
风险 评价维度可能不公平：比如延误可能不是供应商的错（是甲方变更导致的），但数据上会归因给供应商
依赖 需要积累足够的历史数据才能有统计意义（至少3-5个项目）
需要你确认
Q1 你现在合作的供应商大概有多少家？每年新增多少？数据量够不够做统计画像？
Q2 供应商评价维度你觉得哪些最重要？除了我列的那些，还有没有你们特别在意的？（如配合度、主动解决问题能力等）
Q3 供应商画像是否要分享给甲方/第三方？还是仅内部招标决策用？
三、整体评估 & 落地建议
关键依赖链总览
下面是这7个Skill之间的数据依赖关系，越靠左的Skill越基础，后续Skill都依赖它：
Skill1 合同结构化 → Skill2 请款核验 ↘ Skill5 结算回溯
Skill1 合同结构化 → Skill3 变更分析 ↘ Skill4 交叉核验 → Skill5 结算回溯
Skill1-5 全数据 → R1 风险预警 R2 供应商画像
建议落地顺序：先做 Skill 1（合同结构化）→ Skill 2（请款核验），这两个是基座。Skill 3-5 和 R1-R2 可以在数据积累到一定量后再上线。
